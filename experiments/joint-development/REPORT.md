# Codebook-free Naibbe recovery: development record

Development results on development text only. Nothing here is a fresh evaluation, a Voynich
result, or a translation. The [protocol](PROTOCOL.md) for a fresh run is drafted and not frozen.

Codebook-free recovery of Naibbe ciphertext moves from no signal (300%+ character error in the
[standard-method report](../standard-decipherment/REPORT.md)) to partial recovery: 12.2%
character error on 5,200 letters of modern Italian and 14.0% on 5,200 letters of historical prose.
The declared gate (CER ≤ 1%, WER ≤ 10%) is not met.

**Piece:** a glyph string that stands for one letter; a Naibbe token is one piece or two.
**Role:** whether a piece is a whole token, the first part, or the second part; the same glyph
string can encode different letters in different roles.
**Joint EM:** a trigram hidden Markov model over letters in which each token's parse into
pieces is a latent variable, learned together with the piece emissions.
**Oracle segmentation:** the true parse read from the encoder trace. Diagnostic only; it
separates the mapping problem from the segmentation problem and never enters the method.

## What was done

- Added a variable-length key beam with a description-length partial score, iterated local
  search, and simulated annealing (`voynich/variable_units.py`).
- Added joint segmentation-and-decipherment EM and greedy re-segmentation under a fixed key
  (`voynich/joint_segments.py`); forward-backward is checked against brute force in `tests/test_joint.py`.
- Measured recovery against passage length on Novellino/Decameron development tales and ISDT dev.
- Wrote a reproducible development driver (`experiments/joint_development.py`) and a draft protocol.

## Why

The standard-method report left the Naibbe gate untested rather than failed: the published
one-letter model class cannot express Naibbe's one/two-letter units. The question was whether a
method in the right class, with no codebook, recovers the text, and if not, which component fails.

## Failure decomposition

```text
Naibbe token  ->  1 or 2 pieces  ->  1 letter each, depending on role
                  (segmentation)     (mapping: ~300-400 unit types, 4-25 occurrences each)
```

The two sub-problems were tested separately with the oracle segmentation, then together.

### Mapping with the oracle segmentation

Exploratory runs, not regenerated by the driver; historical development text unless stated.

| Method | 1,300 letters | 2,600 | 5,200 | 10,400 |
|---|---:|---:|---:|---:|
| Key beam, width 512 (partial MDL score) | 80% | 78% | 78% | 78% |
| Key beam, width 16,384 | 77% | | | |
| Iterated local search after beam, 400 kicks | 77% | | | |
| Simulated annealing, 4 restarts × 2M proposals | 79% | | 67% | |
| Trigram-HMM EM, 6 restarts | 77% (24 restarts) | 20% | 9% | 5% |
| EM then iterated local search | | **4.6%** | **3.2%** | |
| Same, modern text | | 77% | 3.2% | |

1. **The objective is right; the search was wrong.** With the true role-tagged pieces, the true
   key costs fewer bits than every beam, annealing and local-search result, by 1,000–20,000 bits.
   Only EM finds that basin. Role tagging matters: without it, a deterministic key does not exist,
   because 32–51 pieces per passage encode different letters in different roles.
2. **Length is a hard limit.** At 1,300 letters, EM fails with 24 restarts. The class has 300–400
   free unit assignments; 1,300 letters is near its unicity distance under a character prior. The
   earlier benchmarks used 1,200–1,800 letters, so their Naibbe negatives were partly a length
   effect. Recovery appears between 2,600 and 5,200 letters and is not yet stable at 2,600.
3. **EM tolerates little segmentation noise.** Corrupting 5% of token types in the oracle
   segmentation raises error from 9% to 17%; 14% collapses it to 77%.

### Segmentation without the codebook

Deterministic two-part-code induction (`induce_pieces`, role-aware) reaches 64% exact-token
agreement at 1,300 letters and 88% at 10,400. Most remaining errors are splits at the wrong
position (507 of 789 at 10,400 letters); 4% of tokens are ambiguous even with the true lexicon.
Fixed to that segmentation, EM collapses at every length, consistent with the noise tolerance above.

### Joint model

Joint EM removes the fixed segmentation. Its first version degenerated: rare whole tokens acted as
free wildcards and every token became one letter, because a shorter derivation has fewer factors.
Gating the whole-token parse behind the same frequency threshold as splits fixed that.

| Text | Letters | Threshold | Segmentation agreement | Joint CER | After refinement |
|---|---:|---:|---:|---:|---:|
| historical | 2,600 | 3 | 83% | 70% | |
| historical | 5,200 | 3 | 79% | 54% | |
| historical | 5,200 | 6 | 87% | 35% | |
| historical | 5,200 | 10 (100 iterations) | 83% | 37% | 23% |
| historical | 10,400 | 6 | 85% | 34% | 15% |
| modern | 5,200 | 6 | 89% | 28% | **12%** |

Refinement re-tags the decoded segmentation as role units and runs iterated local search from
the majority key. Two follow-ups did not help: greedy re-segmentation under the refined key
lowered agreement (88% to 80% modern, 85% to 75% historical) and raised error to 21–24%; a warm
restart of the joint EM from the refined key left agreement at 88% and error at 12% (modern,
5,200 letters, two rounds: 12.1%, 12.2%, 11.7%). The reproducible table with the driver's
fixed settings is in `results.json`. Recovered text is readable but wrong in places:

> corrieresportdapaginaapaginaitreavevanodapoco**imasciaelacimaestavanocomincindoladiscesatuttiliessiium**
> corrieresportdapaginaapaginaitreavevanodapoco**lasciatolacimaestavanocominciandoladiscesatuttigliesser**

## What this does and does not establish

- A codebook-free decoder can recover most of a Naibbe passage of 5,000+ letters when the
  source language and alphabet are known and the token class is declared. It cannot yet meet
  the letter gate; the residual error is dominated by segmentation, which the current joint
  model gets 85–89% right.
- The artificial variable-homophonic control remains unsolved by every method here. Its atomic
  tokens share no sub-token statistics, so it is out of class for the joint model; the
  variable-length beam fails on it even at 10,400 letters (truth 40,869 bits, best found 60,586).
- Passage length must be part of any negative claim about cipher recovery. The next
  protocol uses 5,200–6,000 letters.
- None of this concerns Voynich text. The reserved Voynich mechanism test stays closed until the
  fresh-evaluation gate is met or a declared weaker gate is adopted in a committed protocol.
